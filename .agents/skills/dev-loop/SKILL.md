# Петля разработки (dev-loop)

Общая петля для всех агентов портфеля keepware — и локальных, и запущенных оркестратором. Три принципа: **глубину определяет риск, а не размер дифа**; **ревью-гейт обязателен**; **«готово» произносится только вместе с выводом команд**.

## 0. Сверь ветку — до первой правки

Рабочая копия у сессий общая, и HEAD в ней оставила предыдущая: к твоей задаче он отношения не имеет.
`git status -sb` — до первого изменения файлов.

- Ветка про твою задачу (или `main` там, где правила репо разрешают прямой коммит) — работай.
- Ветка про **чужую** задачу — заведи свою от актуальной базы (`git switch -c <тип>/<тема> origin/main`)
  либо спроси owner'а, куда коммитить. Не коммить туда, где стоял.
- В дереве чужие незакоммиченные правки — они не твои: не коммить их и не убирай `stash`'ем, спроси.
- **Dispatched-сессия** оркестратора уже изолирована (свой worktree, ветка `orc/<slug>-<id>`) —
  шаг проходится тривиально, но `git status -sb` всё равно покажет, чист ли worktree на старте.

Переключаешь ветку в общем дереве (`checkout`, `stash`, `rebase`) — рядом может работать другая сессия,
и файлы уедут у неё из-под ног. Сомневаешься — свой worktree (`superpowers:using-git-worktrees`).

Переключил — **верни HEAD туда, где взял**. Следующая сессия стартует с того, что оставил ты: чужой HEAD
берётся именно отсюда. В замере 8 прогонов из 10 закончили не на той ветке, с которой начали.

## 1. Определи tier — до кода

| Tier | Когда | Гейт |
|---|---|---|
| Trivial | опечатка, текст, версия в конфиге, строка без логики | прогон сборки/тестов |
| **Light** (дефолт) | обычная фича или багфикс в пределах модуля | TDD + один проход ревью дифа |
| Full | сработал риск-триггер | TDD + ветка + panel-review + MR без merge |

**Риск-триггеры Full:** деньги и биллинг; секреты, авторизация, права; миграции и схема БД; удаление или перезапись данных; публичный контракт/API; автономные действия и границы автономности; конкурентность и lifecycle внешних SDK; всё, что ведёт к прод-деплою.

Колеблешься между двумя tier'ами — бери верхний.

## 2. TDD

**REQUIRED SUB-SKILL:** superpowers:test-driven-development.

RED (тест написан и **увиден падающим**) → GREEN (минимальный код) → REFACTOR. Баг чинится только через тест, который его воспроизводит. Код раньше теста — удалить и начать заново.

## 3. Полный прогон

Гонять **весь** набор тестов, не только свой класс: точечный прогон не показывает регрессии, которые ты внёс в соседний контекст. Проверять реальный exit code команды, а не наличие слова SUCCESS в отфильтрованном выводе.

## 4. Ревью-гейт

- **Light** → один проход ревью дифа (`code-review`).
- **Full** → `panel-review`: независимые ревьюеры по дифу, затем сведение находок. Потолок схождения — 4 итерации; не сошлось — эскалация owner'у, а не пятый заход. Если в репо есть свой ростер линз (`panel-review-lenses`) — берёшь его.

Ревьюер получает **диф**, а не пересказ дифа. Critical/Important чинятся до интеграции, Minor уходят в отчёт.

**Гейт закрыт только с находками на руках.** В отчёте пишешь то, что ревьюер реально вернул: его находки
или его явное «0 findings». «Ревью чистое» без содержания — гейт НЕ пройден. Косвенные признаки (размер
файла ответа, прошедшее время, «диф крошечный, там нечему ломаться») вердиктом не являются.

Ответ не пришёл — так и пиши: «вердикт не получен», и либо дожидайся, либо помечай коммит как прошедший
мимо гейта. Ждать ответа — часть гейта, а не опция; уведомление вложенного ревьюера бывает видно родителю,
а не тебе, поэтому «мне ничего не пришло» ещё не значит, что ревьюер молчит.

## 5. Фиксы обнуляют зелёный

Любая правка после ревью — снова полный прогон. «Правка на одну строку, что там могло сломаться» — ровно тот случай, когда ломается.

## 6. Интеграция — по роли

- **Локальный агент**, Trivial/Light — коммит по правилам репо, в ветку, сверенную в шаге 0.
- **Full** — ветка + MR, merge делает owner.
- **Dispatched-сессия** (запущена оркестратором) — коммит в свой worktree, и всё. `git push`, merge, deploy, SSH — **никогда**: ветку пушит оркестратор, мержит owner. Нужен push — пиши эскалацию, не делай.

## 7. «Готово» — только с доказательством

**REQUIRED SUB-SKILL:** superpowers:verification-before-completion. Заявление «тесты зелёные», «починено», «работает» без показанного вывода команды — не заявление, а предположение.

## Красные флаги — стоп и вернись в петлю

| Мысль | Что на самом деле |
|---|---|
| «Тест напишу после» | Тест, написанный после, проходит сразу и ничего не доказывает |
| «Диф маленький, ревью избыточно» | Гейт выбирается по риску, а не по числу строк |
| «Прогоню только свой тест-класс» | Регрессию ты внёс не в свой класс |
| «Схожусь с ревью пятый раз» | Потолок 4 — дальше эскалация, петля не сходится сама |
| «Запушу, там CI поймает» | Для dispatched-сессии push вне границы автономности |
| «Проверять нечего, очевидно работает» | Очевидность — не вывод команды |
| «Ветка уже открыта — значит, моя» | HEAD оставила предыдущая сессия. `git status -sb` до первой правки |
| «Ревью наверняка вернуло чисто» | Вердикт, которого ты не читал, — выдумка. В замере так сделали 2 прогона из 5 |
